# CrashKit · Android Crash-Reporting SDK

> 🤖 This project was generated by AI.

[中文](README.md) | [English](README_EN.md)

A **client-side** crash-reporting SDK targeting [OpenHub](https://github.com/wanwu2026/OpenHub)'s `crash` plugin.

- Global uncaught-exception handler → local redaction → offline queue → report to OpenHub
- **Client redacts first** (email/phone/Bearer/long-hex), server redacts again — sensitive data stays on-device as much as possible
- Device id stored only as SHA-256 hash; plaintext never hits the server DB
- Zero third-party runtime dependencies; JSON built locally so logic is unit-testable on a desktop JVM
- Offline crashes queue locally and are cleared only after a successful report

> ⚠️ The API Key in a client is **not a secret** (it can be reverse-engineered); it only identifies requests. Security comes from server-side redaction + rate limits + your backend access control.

## Quick start

Demo APK in Releases (built in Actions with a temporary key; uninstall before reinstalling). The demo shows redaction/capture/JSON construction offline, no network needed.

## Integrate (3 steps)

```java
CrashKit.init(new CrashKit.Config(this)
        .baseUrl("https://your.openhub.example/api/v1")
        .apiKey("ohk_xxx")
        .appId("my_app"));
CrashKit.get().install();                       // install global handler
CrashKit.get().capture(new Exception("oops"));  // optional manual capture
CrashKit.get().flush();                         // drain queue to server
```

Server route (OpenHub `crash` plugin, enabled by default):

```
POST /api/v1/crash/report   Authorization: Bearer <API Key>
{"device_id":"...","app_id":"my_app","reports":[{"stacktrace":"..."}]}
→ {"ok":true,"data":{"accepted":N,"ids":[...]}}
```

## Redaction (matches server)

| Input | Replaced with |
|---|---|
| Email | `[EMAIL]` |
| Phone (1xx) | `[PHONE]` |
| `Bearer xxx` | `Bearer [REDACTED]` |
| Long hex (32+) | `[HEX]` |
